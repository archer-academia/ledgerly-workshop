The hidden judge

The check lives in exercises/…/drills/, outside ledgerly/. The agent can't read it, so it can't copy the rule from it. The only way the rule reaches the agent is what you write.

How good CLAUDE.md files are written

HumanLayer, “Writing a good CLAUDE.md”: it's the only file in every session, so write each line on purpose. WHAT · WHY · HOW. Under 300 lines (theirs is under 60). Only what applies to every task; point to other docs instead of pasting them. “Never send an LLM to do a linter's job.”

Boris Cherny (creator of Claude Code), Jan 2026 thread, as reported: one team CLAUDE.md in git (~2.5k tokens); every time Claude gets something wrong, add a line; tag @claude in PR reviews to add the lesson. And the biggest lever: give Claude a way to verify its work.

Karpathy-inspired guidelines, andrej-karpathy-skills: four behaviour rules: think before coding · simplicity first · surgical changes · goal-driven execution. Project-agnostic, so they complement (not replace) your project facts. The reference's ## How to work borrows them.

Test every line: would the agent get it wrong without it? No → delete it.

Concatenated, not overridden

Every loaded memory file is concatenated. No "more specific wins". When two disagree, the model picks one, and maybe a different one next run.

Strict precedence exists only in settings.json (managed › local › project › user).

# Ledgerly
Invoicing & refunds HTTP API. Python 3.11+, FastAPI,
SQLite, managed with uv. README.md is stale: trust this
file and pyproject.toml.

@docs/standards/api-conventions.md

## Commands
- Install: `uv sync`
- Tests: `uv run pytest -q`
- Lint: `uv run ruff check . && uv run ruff format --check .`
- Architecture contracts: `uv run lint-imports`

## Done means
All four are green. New behaviour has a test.
Report which commands you ran and their result.

## Layout
- src/ledgerly/api/: HTTP only. Never imports repo.
- src/ledgerly/services/: all business rules.
- src/ledgerly/repo/db.py: SQL. Only services import it.
- src/ledgerly/payments/: Money + FX. Own CLAUDE.md.
- docs/decisions/: ADRs. Read the relevant one first.

## Money (ADR-0001)
- Amounts are Money(cents: int, currency);
  convert with payments.fx.convert.
- payments/legacy_fx.py and services/reports.py are
  float legacy. Don't build on them.
- Splitting an amount (installments): every part is
  total // n cents and the last part absorbs the
  whole remainder. 100.00 / 3 → 33.33, 33.33, 33.34.

## How to work
- A request conflicts with an ADR? Stop and say so. Don't work around it.
- Unclear ticket? State your assumptions or ask. Don't guess silently.
- Touch only what the ticket needs. Mention unrelated problems; don't fix them.
- Turn the ticket into a check first (a failing test), then make it pass.
ledgerly/docs/standards/api-conventions.md
Imported with @ · loads eagerly with the project file
## API conventions
- Paths are plural nouns, kebab-case:
  /invoices/{id}/refunds, /reports/revenue.
- Amounts are integers named *_cents, with a
  separate currency field.
- Every error response is RFC 9457 problem details:
  content type application/problem+json,
  body {"type", "title", "status", "detail"}.
- Map domain exceptions to problems in one place
  (api/errors.py), not in each route.

# payments/: money primitives (ADR-0001)
- Money(cents: int, currency) rejects floats on
  purpose. Don't "fix" that.
- Convert with fx.convert(money, to): basis-point
  rates, half-even rounding applied once.
- legacy_fx.py is frozen float code for the old
  revenue report only. New code never imports it.
- Supported currencies: money.SUPPORTED_CURRENCIES.
  Adding one needs a rate in fx.py.
ledgerly/.claude/rules/value-objects.md
Rule · the house style the hidden convention test grades
# Value objects (house style for services/ and payments/)
- Business logic for a ticket goes in a services/ function.
  Routes only map HTTP in and out.
- Every NEW class holding data is
  @dataclass(frozen=True, slots=True, kw_only=True):
  - frozen: a result can't be mutated after a service
    hands it back.
  - kw_only: two int fields (amount_cents, invoice_id)
    can't be swapped positionally. That shipped once (LED-077).
  - slots: no stray attributes.
- Services return value objects, never dicts or tuples
  (no dict, Mapping, TypedDict, NamedTuple,
  tuple[Money, int]). The API maps them to
  pydantic response models.
- Exceptions are exempt. Older classes (Invoice, Line)
  predate this rule; don't copy them, and don't rewrite
  them unless the ticket asks.
- services/reports.py is legacy (dicts and floats).
  It is not an example.
ledgerly/.claude/rules/testing.md
Rule · no paths:, so always loaded (scoping it is the stretch)
# Testing conventions
- Run with `uv run pytest -q`. Tests marked
  `landmine` are deselected on purpose; leave them.
- Name tests test_<behaviour>, one behaviour each.
- Use fixtures from tests/conftest.py:
  conn, client, paid_invoice.
- Assert money as Money or integer *_cents, never floats.
- pytest.raises always takes match= (ruff PT011).
- Never change an existing assertion to make a test
  pass. If an existing test contradicts the request,
  stop and say so.
