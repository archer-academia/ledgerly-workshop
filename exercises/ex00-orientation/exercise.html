2 min

cd ledgerly-workshop tools/doctor.sh

WhyEverything later compares the agent against these gates: tests, lint and the architecture contracts. If they aren't green before the agent starts, every result after that is noise. The 1 deselected is a flaky test parked on purpose for Ex 5.

Stuck? Hints unlock in order

Meet Ledgerly

4 min

Ledgerly is an invoicing and refunds API: FastAPI, SQLite, money as integer cents, three layers. Read the map, then use it once: create an invoice, capture (pay) it, refund it.

ledgerly-workshop/ ← run tools/ from here ├── ledgerly/ ← the sample app · open Claude Code HERE · a local repo (tag baseline) │ ├── src/ledgerly/ │ │ ├── api/ HTTP: routes, schemas (may import services, never repo) │ │ ├── services/ business rules: invoices, refunds, tax, reports │ │ ├── repo/ SQLite, only services may touch it │ │ ├── payments/ Money (integer cents) · fx · legacy_fx (floats!) │ │ └── generated/ "DO NOT EDIT" client │ ├── tests/ migrations/ docs/decisions/ (ADR-0001…0004) │ └── README.md ← written in 2021. Don't trust it ├── exercises/ ← the agent never sees this folder │ └── ex0N-…/ exercise.html · README · LESSONS · drills/ · reference/ ├── tools/ ← start · check · reset · run_drill · doctor … └── runs/ ← transcripts + results (git-ignored)
▶ Start it (a second terminal), then open http://127.0.0.1:8000/docs

uv --directory ledgerly run uvicorn ledgerly.api.app:app

▶ POST /invoices · request body

{"customer": "Acme", "currency": "EUR", "lines": [{"description": "Consulting", "quantity": 2, "unit_cents": 5000}]}

WhyYou'll spend two days judging an agent's changes to this code, so know it first. Note what the response says: net_cents 10000, vat_cents 1700 (17% VAT, ADR-0004), status open. Capture turns it paid; refund turns it refunded. The database is in memory, so a restart wipes it.

Acceptance criteria
You've seen an invoice go open → paid → refunded.
You can name the three layers and which may import which.
Stuck? Hints unlock in order
1 · nudgeWhere are the rules written down?
ledgerly/docs/decisions/: ADR-0001 money as integer cents, ADR-0002 the layers, ADR-0003 refund rules, ADR-0004 VAT rounding.
2 · specificHow are the layers enforced?
ledgerly/.importlinter: api → services → repo, and nothing new may import legacy_fx. uv --directory ledgerly run lint-imports checks it. Notice the two ignore_imports lines: legacy that's allowed, for now.
3 · near-completeRefund says 409
Only paid invoices can be refunded (ADR-0003). Capture first.

Spot the landmines

3 min

Ledgerly works and its tests pass. It also lies, like real repos do. For each README claim, find where the truth lives.

the README saysthe truth is in…what an agent that trusts it does
pip install · make test____runs commands that don't exist
Flask 1.1 · Postgres____writes code for the wrong framework
amounts in decimal dollars____uses floats for money
refunds can be partial____builds on a feature that isn't there

WhyAgents read whatever they find, and the first thing they find is usually the README. Every exercise opens with a drift like this one. The README's own warning banner is there for you; in a real repo there isn't one.

Acceptance criteria
Your table has a source of truth in every row.
Stuck? Hints unlock in order
1 · nudgeWhere do I look?
pyproject.toml, uv.lock, docs/decisions/, and the code itself.
2 · specificMore landmines
payments/legacy_fx.py (floats), api/routes_refunds.py (skips the service layer), .env (fake secrets), generated/ (do not edit), migrations/003_… (applied and destructive), a flaky test. Later exercises use each one.

Anatomy of an exercise

4 min

Every exercise folder has the same shape. Open this one (Ex 0) and look at each part, then peek at Ex 1's names only: no reading the answers yet.

▶ Run in your terminal (workshop root)

find exercises/ex00-orientation -type f | sort ls -R exercises/ex01-claude-md/drills exercises/ex01-claude-md/reference | head -30

partwhat it iswho uses it, and when
exercise.htmlthis page: steps, tickets, hints, timer, locked referenceyou, during the exercise
drills/<ticket>/prompt.mdthe ticket you paste into the agent, word for wordyou · run_drill.sh (headless)
drills/<ticket>/checks.jsonthe list of checks, each with a why printed on failurecheck.sh · run_drill.sh
drills/<ticket>/probe_*.pyhidden judges: call the API, plant bugs, read the diffthe checker, never the agent
drills/<ticket>/setup.shoptional start state (e.g. a feature already built)start.sh runs it for you
drills/<ticket>/reference/red.patch / green.patch: typical bad and good outcomes, hand-writtendemo_reference.sh when a live run won't cooperate
reference/the mechanism that turns red green (CLAUDE.md, rules, skills, hooks…), mirroring ledgerly/after you've tried: apply_variant.sh
README.mdfacilitator notes: timings, fallbacks, what each judge checksthe trainer · you, afterwards
LESSONS.mdthe takeaways + a table for your own numbersyou, at the end of each exercise

WhyDrills, judges and answers live in exercises/, outside ledgerly/. The agent works inside ledgerly/ and reads whatever it finds there, so an answer key next to the code would leak into its context. Keeping the judge where the doer can't see it is a lesson in itself (you'll meet it again in Ex 3 and Ex 6).

Acceptance criteria
For LED-100, you can say what prompt.md, checks.json and probe.py each do.
You know where a mechanism's reference lives and how it gets into ledgerly/.
Stuck? Hints unlock in order
1 · nudgeRead one check
Open drills/led-100-version/checks.json. type: command runs a gate, probe runs a hidden script, diff_present looks at what changed since baseline. Later exercises add transcript_* checks: which commands the agent ran.
2 · specificWhat does a patch look like?
git apply --stat exercises/ex00-orientation/drills/led-100-version/reference/green.patch (run inside ledgerly/) lists the files it touches without applying it.
3 · near-completeWhy not just read the reference?
Because you'd skip the red. Each exercise is built so you see the drift before you fix it. The page keeps the reference locked until you say you've finished.
4

One drill, start to finish

5 min

Every exercise runs the same loop: check first (red), give the agent its ticket, check again, reset. Use Haiku all workshop: fast, cheap, and its mistakes are easy to see.

▶ 1 · Check first: it must be red (workshop root)

tools/start.sh led-100 tools/check.sh led-100 # => RED: GET /version -> 404. A check you never saw fail proves nothing

▶ 2 · Start the agent

cd ledgerly && claude --model haiku

▶ 3 · Paste into your agent · LED-100

LED-100 — Version endpoint

Ops wants to see which build is running. Add `GET /version` returning `{"name": "ledgerly", "version": "<the version in pyproject.toml>"}`.

▶ 4 · /exit, then check again

cd .. && tools/check.sh led-100 tools/reset.sh # back to baseline for Ex 1

PASS tests-pass PASS lint-clean PASS endpoint-works GET /version -> 200, version 0.4.2 FAIL new-behaviour-tested expected change not found => RED (1 failing) ← one possible result; yours may be green
tool (workshop root)what it does
tools/start.sh <drill>ready ledgerly/ for a ticket: baseline code, your memory files kept, the drill's setup.sh applied
tools/check.sh <drill>grade the repo + your newest Claude Code session (read-only; results go to runs/)
tools/reset.sh [--keep-memory]back to the baseline tag. Deletes untracked files unless --keep-memory
tools/demo_reference.sh <drill> red|greenapply a drill's hand-written example and check it, no agent needed
tools/apply_variant.sh <folder>copy a reference/ (or a saved variant) into ledgerly/
tools/snapshot.sh <name>save your memory files to my-variants/<name>
tools/run_drill.sh <drill> <variant> NN headless runs (none, current or a folder) → a pass-rate table

WhyThe checker doesn't read the agent's summary. It grades the repo (tests, lint, a probe that calls the endpoint itself) and, in later exercises, the transcript. Red here usually means "no test for the new endpoint", which nobody asked for. Is that the agent's fault? Ex 1 answers that. Write your result in exercises/ex00-orientation/LESSONS.md: from now on, every exercise ends with your own numbers.

Acceptance criteria
You've read a tools/check.sh report and can say what each check looked at.
Your LED-100 result is in LESSONS.md.
tools/reset.sh put ledgerly/ back to baseline.
Stuck? Hints unlock in order
1 · nudgeNo session found?
check.sh grades your newest Claude Code session for this folder. Start claude inside ledgerly/, not the workshop root.
2 · specificCompare with the examples
tools/demo_reference.sh led-100 red, then … green, then git -C ledgerly diff baseline to see what changed. Finish with tools/reset.sh.
3 · near-completeOne run proves little
Agents are non-deterministic. tools/run_drill.sh led-100 none 3 runs it 3 times headless and gives a pass rate; python3 tools/drift_check.py --summary runs/led-100-version summarises. Every exercise reports rates.
